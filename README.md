# MAX Chat · GREEN-API

Тестовое задание на позицию «Фронтенд-разработчик React». Это веб-интерфейс для отправки
и получения текстовых сообщений в мессенджере **MAX** через [GREEN-API](https://green-api.com/max).
Внешний вид сделан по мотивам [web.max.ru](https://web.max.ru/).

Задание разрешает вместо MAX использовать Telegram, поэтому поддерживаются оба типа инстансов.
Тип определяется автоматически при входе по полю `typeInstance` из `getSettings`:
`v3` — MAX, `telegram` — Telegram.

## Возможности

- Вход по `apiUrl`, `idInstance` и `apiTokenInstance`. Перед входом проверяется состояние
  инстанса (`getStateInstance`) и определяется мессенджер (`getSettings`).
- Новый чат: получатель проверяется через `checkAccount`, который возвращает его постоянный `chatId`.
  - **MAX** — только номера России (`+7`) и Беларуси (`+375`), это ограничение API MAX.
  - **Telegram** — номер любой страны в международном формате или `@username`.
- Отправка текстовых сообщений через [`sendMessage`](https://green-api.com/v3/docs/api/sending/SendMessage/).
  Сообщение сразу появляется в ленте (оптимистичный UI). Если отправка не удалась, её можно повторить.
- Получение сообщений через [HTTP API](https://green-api.com/v3/docs/api/receiving/technology-http-api/):
  цикл `receiveNotification` с long polling, после обработки `deleteNotification`.
- Статусы исходящих: отправляется → отправлено → доставлено → прочитано.
- История и список чатов сохраняются в `localStorage` отдельно для каждого инстанса.
  Входящие от новых собеседников создают чат автоматически.
- Адаптивная вёрстка: на телефоне показывается либо список чатов, либо открытый чат.
- Тёмная тема (как у MAX) и светлая, переключаются по системной настройке.

## Быстрый старт

Нужны Node.js ≥ 20.19 (см. `.nvmrc`) и pnpm.

```bash
pnpm install
pnpm dev
```

Приложение откроется на http://localhost:5173.

Сборка production-версии:

```bash
pnpm build
pnpm preview
```

Папка `dist/` содержит статический SPA и разворачивается на любом статическом хостинге
(Vercel, Netlify, GitHub Pages). Бэкенд не нужен: GREEN-API отдаёт CORS-заголовки.

## Подготовка инстанса GREEN-API

1. Создайте инстанс MAX или Telegram в [личном кабинете](https://console.green-api.com)
   и авторизуйте его.
2. В настройках инстанса **оставьте пустым `webhookUrl`**: при заданном webhook метод
   `receiveNotification` недоступен.
3. Включите уведомления о входящих сообщениях. Для синхронизации сообщений, отправленных
   с телефона, включите ещё и исходящие.
4. Скопируйте `apiUrl`, `idInstance` и `apiTokenInstance`. `apiUrl` у каждой группы
   инстансов свой (например, `https://7103.api.greenapi.com`), общий хост подходит не всем.

Если настройки инстанса мешают получать сообщения, приложение покажет предупреждение.

## Сценарий проверки

1. Откройте приложение и введите `apiUrl`, `idInstance` и `apiTokenInstance`.
2. Нажмите «+», введите номер получателя (для Telegram можно `@username`) и нажмите «Создать чат».
3. Напишите сообщение и отправьте его клавишей Enter (Shift+Enter переносит строку).
4. Ответьте с аккаунта получателя. Ответ появится в чате.

## Стек

React 19, TypeScript (strict, `noUncheckedIndexedAccess`, `exactOptionalPropertyTypes`),
Vite, Zustand, CSS Modules, Vitest, Testing Library, oxlint, Prettier.

Из runtime-зависимостей только `react`, `react-dom` и `zustand` (~1 КБ). Иконки
написаны inline-SVG, UI-кит не используется. Бандл весит около 81 КБ в gzip.

## Архитектура

```
src/
├── api/                    # работа с GREEN-API, без React
│   ├── greenApiClient.ts   # типизированный клиент: таймауты, отмена, понятные ошибки
│   ├── notifications.ts    # разбор уведомлений в доменные события
│   ├── polling.ts          # цикл receive → handle → delete с экспоненциальным backoff
│   └── GreenApiContext.ts  # DI клиента через React Context
├── domain/                 # доменные типы: Chat, Message, тип инстанса (MAX / Telegram)
├── store/                  # Zustand-сторы
│   ├── chatStore.ts        # чаты и сообщения, дедупликация, статусы, persist
│   └── sessionStore.ts     # учётные данные (sessionStorage)
├── hooks/                  # useNotificationPolling, useSendMessage
├── lib/                    # чистые функции: телефоны, получатель, даты
└── components/             # UI: auth/, sidebar/, chat/, ui/
```

Ключевые решения:

- **Слои разделены.** Транспорт (`api/`) не знает о React, а бизнес-логика стора — о сети.
  Цикл polling и парсер уведомлений — чистые функции, поэтому они тестируются без DOM.
- **Надёжное получение.** Long polling (`receiveTimeout=20`) даёт почти мгновенную доставку
  без частых запросов. Уведомление удаляется из очереди, даже если обработчик упал, поэтому
  одно битое сообщение не блокирует очередь. После сетевых ошибок повторы идут
  с экспоненциальной задержкой и джиттером, а на 401/403 цикл останавливается.
  При размонтировании запросы отменяются через `AbortController`.
- **Идемпотентность.** Сообщения дедуплицируются по `idMessage`, так что повторная доставка
  уведомления ничего не ломает. Бывает, что `outgoingAPIMessageReceived` приходит раньше
  ответа `sendMessage`, и этот случай тоже обработан. Статусы никогда не понижаются
  («прочитано» не станет «доставлено»).
- **Защита от неожиданного формата.** Ответы API проверяются type guard'ами. Неизвестные
  и нетекстовые уведомления не роняют интерфейс.
- **Производительность.** Селекторы Zustand подписывают компоненты только на нужные данные.
  `memo` стоит на элементах списков, стабильные колбэки и константный пустой массив
  избавляют от лишних рендеров. Форматтеры `Intl` создаются один раз. В `localStorage`
  хранится не больше 200 последних сообщений на чат.
- **Безопасность.** Токен хранится только в `sessionStorage`: он переживает перезагрузку,
  но удаляется при закрытии вкладки. Текст сообщений выводится как текст, без
  `dangerouslySetInnerHTML`.
- **Доступность.** Семантическая разметка, `aria-label` у иконок-кнопок, `role="log"`
  у ленты, видимый фокус, поддержка `prefers-reduced-motion`.
